## Problem

The interior-design app guided users through fixed buttons, one step at a time. People could not ask what they actually wanted, and the app could not use what it already knew about their taste.

## What I built

I proposed replacing the button flow with an AI chat and led the build. It runs on LangGraph, which manages the conversation, the tools the AI can call, and what it remembers. Claude handles the conversation and Gemini generates room images, and I tested and debugged the agent with LangSmith. A quiz sorts each user into one of **31** design concepts, then the app renders a makeover of their room and recommends real furniture from a catalog of **40,000+** products. Behind this sits a knowledge graph of **40,000+** nodes on Neo4j that links each concept to materials, colors, and product traits.

## Architecture

The chat agent decides which tool to call: the quiz, the recommender, or the image generator. Recommendations use GraphRAG, meaning the agent walks the knowledge graph to find what fits a concept and budget, then writes a detailed image prompt from the result. A scraping pipeline keeps the product catalog fresh.

```
Flask API → LangGraph agent → Claude + Gemini → Neo4j knowledge graph (GraphRAG) → product catalog
```

## Result

- Chat became the main way users use the product, and the old button interface was retired
- Knowledge graph of **40,000+** nodes covering **31** design concepts
- Recommendations drawn from a catalog of **40,000+** products

## Troubleshooting

Problem: the recommendations ignored the user's context and taste. Cause: a plain product search had no way to connect a design concept to materials, colors, and product traits. Fix: I built a knowledge graph of **40,000+** nodes on Neo4j (**31** concepts linked to materials, colors, and products) and generated prompts with GraphRAG. Result: recommendations are now built from the user's own concept and context.
